# 現場の空 v0.35 — 高水準の予報精度検証と補正開始の条件

更新：2026-11-10

## 結論：データが一定件数に達しても、自動補正は直ちには始まらない

「月や季節によって予測の得意・不得意が異なる」という仮説を検証するため、まず全国アメダスの公開観測値と3モデルの予報を適正に突き合わせる。**誤差が一時的に小さくなっただけで予報を変更しない**。

今の段階で実装したのは、(1)2年程度の長期照合履歴、(2)高水準のデータ充足判定、(3)複数の誤差や強風・降水の見逃しを分ける診断。**補正をかけるエンジン、未学習の期間での補正モデルの比較、モデルを自動で選ぶ機能、切替・復帰スイッチはまだ本番には組み込んでいない**。従って「十分に貯まったら自動で開始する」という挙動はまだない。

## 取り込む条件
- **地域**：全国の公開アメダス観測所。まず9地点のモデル別予報と照合。地域別成績を検証できるのはその地域の公開観測所が十分に増えた後。個人現場のGPSは研究へアップロードしない
- **季節と月**：春・夏・秋・冬、暦の12か月を別々に評価。同じ月の複数年のデータを重ねて、特定年の異常天候への過適合を減らす
- **予報時間**：3、6、12、24時間先を別々に評価。現状の収集系は6・12・24時間先で、**3時間先は未収集**
- **昼夜**：日本時間で6:00～17:59を昼、それ以外を夜として区別。日の出・日の入りの変動は将来の改良余地
- **風速**：MAE、RMSE、平均バイアス、絶対誤差の90パーセンタイル。8m/s以上の研究用強風カテゴリについて見逃し・的中・空振りの件数も表示
- **風向**：0°と360°が近い円周角誤差
- **降水**：過去1時間の積算降水mm。MAE、0.1mm以上の降水有無、5.0mm/h以上の研究用強降水カテゴリの見逃し・空振り
- **欠測**：品質フラグが不良、予報モデルが1つ欠ける、風や雨のデータが欠ける場合は「3モデル共通の比較データ」として数えない。0mmと欠測は区別
- **観測所の風と現場の風**：10m風の格子予報と観測所の観測条件・標高差を明記。山林や樹上の安全に直結する補正と断定しない

## v0.35の厳格なデータ充足基準（試験運用値）

| 必須の条件 | 検証開始に必要な最低値 |
|---|---:|
| 収集対象期間の長さ | 540日 |
| 重複を除いた暦の日数 | 300日 |
| 共通の公開観測所 | 5地点 |
| 異なる暦月の数 | 12か月 |
| 季節の網羅 | 4季節 |
| 各季節で確認できた日数 | 40日 |
| 各暦月で確認できた日数 | 10日 |
| 過去（訓練用）の独立日数 | 210日 |
| 新しい期間（検証用）の独立日数 | 90日 |
| 3モデルが同条件で揃う地点・時刻 | 1,000組 |
| 降水を実測した独立日数 | 45日 |
| 風速8m/s以上を実測した独立日数 | 20日 |
| 検証期間に降水した日数 | 10日 |
| 検証期間に8m/s以上があった日数 | 5日 |

**これらの数値は「現場の空」が独自に設定した保守的な試験上の基準であり、WMOやECMWFが全用途に定めた普遍的合格点ではない。** ただ数を満たすだけでは精度向上の証拠にならない。今の段階では、上記をクリアしても「補正候補の独立検証を開始できるかもしれない」という判定にとどめる。補正は引き続きオフ。

- 日数は同じ日に多数の観測所から得た100件を100日とせず**1日**と数える。観測回数だけで見せかけの学習量を増やさない
- 3モデルが同じ公開観測所・同時刻・予報リード時間に風と1時間降水を**すべて**提供したものだけ共通サンプル
- 旧データは14日/21日で消えるため、その前に照合したコンパクトな**公開観測所のみ**の予報・実測ペアを日別の圧縮ファイルで最大730日保存する。ただし観測遅延への配慮として**日本時間の該当日から2日後以降**に確定し、1日につき**同条件の3モデル完全照合が5組以上**ある場合のみ保存する。初回収集以前の過去予報が自動的に復元されるわけではない
- `data/model-validation/status.json` の `match_archive_progress` で、正式保存を待つ照合件数・3モデル完全照合数・日別の確定可能日・必要な照合数の不足を確認できる。**pendingは学習完了や補正適用を意味しない**。正式保存済みは `correction_readiness.records_archived` を参照する
- `tools/correction_readiness.py` で条件不足を明示し、`tools/forecast_skill_audit.py` は成績を月・季節・地域・昼夜・予報時間で集計
- ダッシュボードでは誤差成績の診断に必要な独立日数が30日未満なら数値を「—」相当とする。強風・降水イベントの成績はイベントが15日未満なら非表示。**30日/15日は診断の最低値であって、補正を自動採用できる最低値ではない**

## 将来の自動補正の採用条件（まだ未実装）
1. 同じデータで学習と合否判定を行わない：時系列で分けた未使用期間で評価する
2. 補正前の最も成績のよいモデルだけでなく、複数モデルの基準値（中央値や安全側の予測上限）とも比較する
3. 風・降水それぞれのMAE/RMSE等が統計的に安定して改善していることを、日単位ブロックによる信頼区間で検証する
4. 強風・強降水・冬期の悪化、降り始めの見逃し、ある季節/地域だけの悪化がないか確認する
5. 地域・月・予報時間のうち条件がそろわない区分には補正を適用しない。全国で一つの「最適モデル」に決めつけない
6. モデルの更新・データ欠測・取得遅延・著しい精度悪化に対して補正を自動停止し、元の予報にフォールバックする
7. 補正した値でも、強い風や雨を予測するモデルがあることを隠さない。気象庁の警報・注意報・会社の作業中止基準が最優先
8. 実際の補正自動適用機能は、これらをテストしてから**別のリリースとして明示的に実装**する。現時点で自動オンになることはない
