# 現場の空 v0.46 — 地点の地面の標高と気温観測所の標高差

## 要件と配置
箱根周辺で選択地点の予報が12.4℃、小田原アメダスの実測10.5℃、観測所標高14mという画面から「今いる地点の標高を知りたい」とユーザーが要望。

- 「近くのアメダス実測」内で、従来の気温比較の**直下**に「⛰️ この地点と観測所の標高」を追加。
- 3列は **この地点（GPS現在地／保存現場／検索した場所）**、**気温観測所の標高**、**標高差（地点−観測所）**。
- 「⛰️ この地点の標高を調べる ♡」を本人が押したときだけ外部標高APIへ緯度経度を送る。**GPSを自動でバックグラウンド送信しない**。
- まず国土地理院公式の [経緯度から標高を求めるAPI](https://maps.gsi.go.jp/development/elevation_s.html) を利用（`getelevation.php`、JSON形式）。これは数値標高モデル（地面の標高）であり、iPhoneのGPS楕円体高でも予報モデルの格子点標高でもない。
- GSIのCORS失敗、欠測、国土地理院API停止時は Open-Meteoの [Elevation API](https://open-meteo.com/en/docs/elevation-api)（約90m Copernicus DEM）へ切り替える。**必ず低解像度の参考値と出典を明記**。
- 非国内地点でもGSIのデータが無ければOpen-Meteoへフォールバックできるが、対象の高度や精度を保証しない。
- 観測所標高は既存の気象庁観測所定義 `meta.alt`。気温を観測している最寄り観測所を使う（従来の風速／雨量観測所と異なることがある）。
- 標高が取得できない／観測所の標高がないときは数字を捏造せず `—` とする。
- 同じ端末上の座標切替・遅延HTTP応答・圏外の取り扱いに注意。古い地点の標高は切替直後に消し、遅延した応答を無視する。端末内に標高履歴やGPSログを蓄積しない。
- この比較は別地点の参考比較であり、気温の自動補正・3モデル研究・全国アメダス解析・気象通知・現場保存・私用お気に入りは変更しない。
- 地形データは建物の高さ、今いるフロア、GPSの測位誤差を表していない。地形・標高差の存在が、予報値との差の原因だと断定する材料にはしない。

- GitHub Actions `home-site-navigation-check.yml` に自動テストを追加。既存の天気表示・実測気温・通知・検索・Service Workerなどの回帰テストも維持。
