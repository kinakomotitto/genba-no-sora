# 現場の空 v0.37 — 学習基盤の信頼性・検証品質・異常検知

更新：2026年11月10日

## この変更の意図
学習アルゴリズムをむやみに増やすのではなく、**保存・照合する実測と予報が正しく、比較が公平で、異常なときに誤った採点や補正が進まない状態**にする。

本番のiPhoneホームの予報、現場GPS、通知は**一切補正していない**。自動補正は本番OFF。安全装置は研究・シャドー（裏側の試験）専用で、現場の作業安全を保証する機能ではない。

## ① 3モデル収集の安定性と失敗原因
- 3モデルの収集はGitHub Actionsから6時間ごと。モデルの予報を9→18→27→最大36地点の**公開アメダス代表観測所**で検証。元の9代表地点を保持する
- 公開観測所の一覧で、**前回選択した地点を優先的に維持**。一時的な欠測で代表地点が入れ替わり、時系列の比較が不安定になることを抑える
- Open-Meteoのリクエストは**1バッチ最大9地点、1回最大16GET**。外部API制限を強引な連続リトライで回避しない
- HTTP 401/403/429を受けた場合、**その実行では残りの外部予報リクエストを停止**。APIのレート制限・提供者のアクセス制限を尊重する
- 3モデルそれぞれについて成功観測所数、欠けたバッチ数、限定されたエラー分類を保存。エラー本文、URL、トークン、個人位置はGitHubの公開データへ出さない
- **HTTP 401/403/429でリクエストをその場で中断**。レート制限が疑われるのに残りのモデルを連続照会しない。提供元の許諾や利用制限を回避しない
- 1モデルにおいて一部の地点や必要な予報対象時刻が欠けた場合は、そのモデルを「完全に成功」と扱わない。部分成功を `partial`、全失敗を `unavailable` と明示
- 毎回データを取得できていても、**少なくとも3モデルが完全にそろわない限り正常状態にしない**
- 次の本番定期実行が連続成功するかは別途確認が必要。**このリリースだけでOpen-Meteoの通信問題が解決したと断定しない**

## ② データ照合・品質
- 予報・実測は公開アメダス観測所のIDと同じ予報対象時刻で突き合わせる
- 3モデルの公平な共通サンプルは、**風と1時間降水量が全モデルで欠測せず**、**予報取得時刻の差が15分以内**、**照合した同一時刻の実測値が全モデルで一致**した場合のみカウント
- 0mm（降水なし）と欠測（None）を区別し、気象庁の品質フラグによって未確認値を混ぜない
- モデルの1つが欠けたり、1地点だけ雨の予報が欠けた場合、「共通して採点可能」とは誤認しない
- 地域分類は元の9代表地点に加え、追加観測所を「青森近傍」など**最寄りの代表地点に基づく公開データの研究用近傍区分**へ分類。「東北」などの行政区域を精密に特定したものではない
- 観測所の標高・風の測定条件とモデル予報の格子・高さは一致しない可能性があり、山林や樹上の実風速をそのまま示すものではない
- 1時間降水量の積算終了時刻がそろわない予報・観測は採点しない

## ③ 季節・月・地域の独立検証を厳しくする
- 210日以上の先行する学習期間と90日の**未使用期間**を分ける単一検証に加え、**時間をずらした別々の90日検証を最低4回**行うローリング方式を追加
- **最低570独立日の履歴**がないと4回の季節横断テストができない（候補が昇格するための追加条件）。これとは別にv0.35の**540日以上の履歴、300独立日、全12か月、4季節、風雨の十分なイベント件数**も必要
- 同じ日に大量の観測所の情報があっても、日数は**1日**と数える
- 各試験では未来の検証期間を使ってモデルや補正パラメータを決定しない
- 風速のMAE・偏りと、**強風の見逃し**、降水の誤差・雨と強い雨の見逃しを別々に評価。補正しても全体の平均誤差が良いだけで、地域別の悪化や新しい見逃しがあれば候補を落とす
- 日単位の対応ブートストラップによる改善下限も確認する
- 4回すべての検証期間で風と雨の試験条件に合格し、**春夏秋冬をまたいだ実測データがそろわない限り候補を昇格させない**。条件は厳格な研究用試験値であり、特定の気象機関が全用途に認証した基準ではない
- たとえ全て合格しても **本番補正は自動的に有効化しない**。使用地域や日付での安全性確認、実際の本番切戻しが別途必要

## ④ 3回連続失敗で異常通知、回復したら自動解除
- `tools/weather_collection_health.py` が、全国アメダス実測、3モデルの予報、精度検証結果の**9時間以内の更新・地点数・完全な3モデルの有無**を確認
- 有効な全国観測地点が200未満、または**前回から20%以上減少**した場合、風・雨いずれかの有効観測地点が200未満、観測データの出典が想定と異なる場合も異常とする。予報3モデルは名前まで照合し、異なる3モデルや予報0件を正常扱いしない
- 連続して健康状態が `degraded` と判定された定期実行を記録。途中で8.5時間を超える空白があれば「連続」と数えない
- **3回連続で異常**が起きたときだけ、`tools/research_failure_issue.py` がGitHub Issuesに**1件だけ**異常報告を作成。同じ異常で同じIssueを複数作成しない
- 正常に戻ったら、開いている自動異常報告Issueを閉じる
- GitHub Issuesが動かない・権限不足でもデータ収集を止めない（通知はベストエフォート）
- **GitHub Issueの作成自体がiPhoneプッシュやChatGPTの通知到達を保証するわけではない**。GitHub側のWatch/通知設定に依存する
- 既存の「自動補正完成を知らせるChatGPTの週次チェック」とは別の目的。通知が鳴り続ける仕組みにしない

## 品質検証・公開状況
- テスト：APIの部分成功、欠測データ、取得地点の固定、連続異常・回復、時刻の不一致、4季節のローリング検証、地域別悪化の拒否、アプリのホーム・現場の表示を確認
- ソース公開と自動テストの成功は、**本物の外部APIの連続稼働成功を示すものではない**。6時間ごとの本番運用記録で確認
- GitHub PagesのPWAは v0.37。現場画面の基本動作は従来どおりで、設定の「予報の蓄積状況」に連続異常回数を表示
- さらに必要な確認：次の複数回の予定収集で3モデルの応答、実測と同時刻の照合ペアが作成されること、シャドー補正がオフのままであること、GitHub Issueの実運用が許可されていること
