# 現場の空 v0.41 — ポケットに届く気象変化通知（任意の試験版）

記録日：2026-11-11。**この機能は気象庁の警報・落雷監視・安全管理システムではありません。モデル予報の参考通知だけです。**

## できること

- iPhoneのホーム画面に追加された「하늘」の「現場 → 通知設定」で、「📍 今の地点で4時間の天気通知をオンにする」を**本人が押す**と開始
- iPhoneのホーム画面アプリを閉じていても、既存のCloudflare Workerの15分間隔Cronが**最後に登録した現在地**に対して、Open-Meteoの今後2時間のモデル予報を確認
- 雨（15分補間予報の降水量が0.5mm以上）、予報の最大瞬間風速15m/s以上、雷雨の**気象モデル予報コード95,96,99**があれば、1つのまとめたWeb Pushの送信を試みる。通知は「参考予報」「最後に登録した地点」と明記
- 多重通知を避けるため、**同じ登録地点は2時間に1回まで**を目安にする。端末がオフライン／iOS側のプッシュやサーバー障害で届かないことがある。時刻の保証はない
- 4時間で監視が**期限切れ**。ユーザーが停止ボタンを押した場合はサーバーに保存した監視地点を削除する。期限切れデータは次回Cron処理で削除する（Cron障害時は遅れる）。自動延長はしない
- 既存の「晴れ／曇り／雨／雪」の目視記録、全国アメダスの研究用モデル検証、毎日選択時刻の天気記録リマインダーは維持

## 重要な制約

- **閉じている間にGPSを自動追跡することはできない。** iPhoneホーム画面PWAでバックグラウンド位置更新は保証されない。移動したら、アプリを開き、監視開始ボタンでGPSを取り直す必要がある
- 日本国内のOpen-Meteo `minutely_15` は主に**時間ごとの数値予報を15分へ補間した系列**で、現地レーダーで判定した到着時刻ではない。「あと17分で雨」「あと5分で強風」のような秒・分単位の断言をしない。『この先2時間』と表現
- **雷雨の予報 ≠ いま付近に落雷が接近した実況情報。** モデルが雷雨を予報しない場合、雷の通知が来ないことがあり得る。気象庁の雷ナウキャストや公式警報とは別物。雷鳴が聞こえるなどの兆候があれば通知を待たない
- 「風速15m/s」は**モデルに基づく参考通知基準**であり、送電線路伐採・チェーンソー・高所・樹上作業の作業停止基準を設定するものではない。会社の安全基準と最新の公式警報を優先
- レーダーによる「雨雲の実測・高解像度降水ナウキャスト」「雷の実況接近通知」は、正式APIと利用条件・精度を確認する必要があり**今回は未実装**
- 予報が外れる・通信断・通知遅延・圏外・運用停止は起こり得る。通知がないことは安全な証拠にならない

## 位置情報と通知先データ

- プッシュ通知はユーザーがiPhoneで明示的に購読。選択時刻の定時リマインダーとの併用、**気象通知だけの購読**の両方に対応
- 気象通知を本人がオンにするときだけGPSを新しく取得する。要求精度は300m以内、記録時刻は5分以内
- プッシュ購読の本人確認には既存の非公開トークンを使う。Cloudflare D1非公開の `weather_watch` テーブルに、**小数3桁に丸めたGPS座標**・監視開始/期限切れ・最後の通知時刻を記録
- 気象予報を取得する際、丸めた緯度経度をOpen-Meteoへ送信。個人の保存現場の名前・メモ・目視天気記録・正式な住所は送信しない
- 監視停止時にGPSのレコードを削除。iPhoneで「通知をすべてオフ」にすると同じサーバーの通知先登録も解除（既存の通知解除操作は維持）
- 登録処理ができない場合・位置情報取得に失敗した場合は監視を開始しない。アプリを開いただけでGPSをクラウドへ送る処理は追加していない
- Cloudflare側のWeb Push用購読鍵・通知トークン・D1のレコードはGitHubへ保存しない

## APIと運用

- `POST /api/weather-watch-enable`：プッシュの正当な購読者のみ・`consent:true`・新しいGPSが必要。レコードの有効期限4時間
- `POST /api/weather-watch-stop`：監視停止・登録座標を削除
- `POST /api/weather-watch-status`：期限切れかどうか・登録時刻・終了予定時刻だけを返す（座標を戻さない）
- `POST /api/subscribe`：`weatherOnly:true,times:[]`で日次通知無しのプッシュ購読も可能。すでに日次通知がある場合は時刻設定を保持
- 15分ごとの既存Cronに「気象変化の通知」を並列に追加。Weather Watchでエラーになっても既存の日次リマインダーは独立して処理
- 既存D1に対して `CREATE TABLE IF NOT EXISTS` で追加テーブルを準備。既存の通知テーブルを変更・消去しない
- 試験運用につき**1回のCronで最大20地点**を監視。長時間バックエンドが使えない場合は通知が届かない
- 今回のCIは**オフラインの擬似GPS・API・Web Pushでの単体テスト**。Cloudflare本番でのCron・iPhone受信は必ず別途実機で確認し、CI成功だけで確実性を主張しない
