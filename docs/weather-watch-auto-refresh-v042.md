# 現場の空 v0.42 — 初回設定だけで、アプリを開くたび現在地の通知監視を更新

更新日：2026-11-11

## 選択した動作

ユーザーが合意した仕様：**「最初に一度だけ天気変化通知と位置情報の自動送信を許可し、以降はiPhoneのホーム画面アプリを開く・前面に戻すたびに現在地を取得して監視地点を自動更新する」**。

- v0.41の手動「4時間ごとに監視開始を押し直す」操作を撤廃
- 最初の1回は設定の「📍 最初の1回だけ自動監視をオンにする」を**ユーザーが明示的に押す**。iPhoneの通知許可・新しいGPS取得・サーバー登録が成功した後にのみ、その端末のローカルストレージに自動更新同意フラグ `genbanosora.weatherwatch.autorefresh.v1` を保存
- 次回以降のアプリ起動時は、既存のGPS取得成功時にその新しいGPSで自動更新。アプリをバックグラウンドから前面に戻した場合は `visibilitychange` を使い再び新しいGPSを取得し、成功すれば監視サーバーの地点と期限（最新更新から4時間）を更新
- 同意のない端末・通知未許可・期限切れ/低精度GPS・ネットワーク断・既存Push購読がない状態では**一切自動登録しない**。アプリ起動時に通知許可のポップアップや新しいPush購読を勝手に行わない
- 新しいGPSが取得できない場合は以前の保存地点を使って監視を再登録しない。直近の古い地点はその位置を最後に更新した時から最大4時間で自動停止
- 保存現場詳細で画面復帰した場合も、通知サーバーに自動送るのは実際の現在地のGPSのみ。保存現場の登録場所・名称を流用しない。天気予報画面の選択地点も上書きしない
- ページ表示のたびや `visibilitychange` 重複イベントによる同一地点の多重送信を10秒間抑制
- ユーザーが「通知監視を終了・位置情報を削除する」を押したら、**まず端末の自動送信同意を無効化**。進行中の位置情報更新要求が終わるまで待ってからサーバーで監視削除し、再び勝手に登録されないようにする
- 通知をすべてオフにした場合も、通信の成否にかかわらず最初に端末の自動送信同意を無効化
- 通知サーバー側の削除が通信不良で未確認なら、**削除できたと断言しない**。端末の自動送信のみ停止済みと表示し、再停止操作を案内

## プライバシーと構造

- 最初の許可操作以外で端末の自動監視を有効化しない。v0.41で一度だけ4時間監視を開始した端末でも、今回の**継続的な自動更新への新規同意**がなければ自動送信しない
- クラウドへ送信する緯度経度は小数3桁に丸める。端末内には同意フラグだけを追加保存し、**正確なGPSや現場名・現場メモ・目視天気記録をこの機能のために外部送信しない**
- リマインダー、全国の観測研究、3気象モデルの検証、GPSでの画面表示、雨雲レーダーは変更しない
- Cloudflare Workersの15分ごとの気象変化判定とWeb Pushはv0.41を維持。雨・風・雷雨の**数値予報に基づく参考通知**であり、公式の警報・実況落雷接近検知・精確な雨の開始時刻を保証しない
- iPhoneのPWAは**アプリを閉じている間にGPSを追跡できない**。移動してもアプリを開かない限り前の地点の予報を監視し、最後の更新から4時間で終了。OSが位置情報や通知を拒否した場合も監視は更新されない

## テスト・運用

- `weather-watch-auto.js` を新規追加し、同意オン/オフ、GPS鮮度・精度、同時更新の抑止と保留処理を単独テスト可能にした
- `tests/test_weather_watch_auto.cjs`：同意前は送信0回、同意後の自動更新、移動後の位置更新、10秒以内の重複抑止、古いGPSや精度不良の拒否、進行中の要求中の停止、アプリ再起動後の継続/停止の保存、キャッシュGPSの不使用、GPS丸め、通知許可の確認、v0.42 PWAシェル
- `tests/test_home_site_navigation.cjs`, `tests/test_weather_watch_sw.cjs` のバージョン回帰テストも更新
- 実機のGPSとiPhoneへのPush配信は、iPhoneで最初の設定を終えてから別途確認する。GitHub Actionsテスト成功だけで通知の確実な到着を主張しない

## 使用者の操作

iPhoneのホーム画面「하늘」 → 「現場」→ 「通知設定」→「📍 最初の1回だけ自動監視をオンにする」。

**この設定を押す前には自動的なGPSアップロードは始まりません。** 本文内で位置情報の送信先と更新条件を確認してから本人が選ぶ方式です。以後、アプリ起動／前面復帰で新しい位置情報を取得できるたび、最後の地点の4時間監視が更新されます。
