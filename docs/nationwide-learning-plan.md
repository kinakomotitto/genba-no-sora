# 全国自動検証の設計 — 全国均等学習 + 重点地域（v0.29試作）

2026-11-10 / 状態：**収集のスケジュール生成は実装、全国の実データ取得は未開始**。

## 目標
初めて訪れる県や離島を含め、全国の公開気象観測所で3つのモデルを継続して採点できる仕組みを目指す。訪問履歴・個人GPS・現場名の収集は不要とする。全国の公開観測所データを使って学習し、iPhoneに表示するのは選択地点付近の軽い集計結果だけ。

## 全国の観測所
気象庁によると降水量観測地点は全国約1,300、風向・風速・気温等の観測地点はそのうち約840。降水量しか測定していない観測所に風速の正解ラベルを作らない。
公開観測所のメタデータ一覧（更新やフォーマットの変更を要確認）：
https://www.jma.go.jp/bosai/amedas/const/amedastable.json
観測所一覧と公式説明：
https://www.jma.go.jp/jma/kishou/know/amedas/kaisetsu.html

**データを網羅する**は全国の地点をカバーすること。全国の全観測所で10分ごとに予報を取得することではない。後者は負荷と利用規約が異なる。

## 取得頻度の設計例（現時点では一切起動していない）
- 全国の公開観測所：各モデルを最低**1日に1回**取得し、指定した複数の予報対象時刻を保存して翌日の観測と比較する。全地点の絶対位置とモデル名を保持する
- 重点観測所：あらかじめ選択した公開観測所最大100地点を6時間に1回（1日4回）に増やす
- 追加の負荷が高い場合は、重点地点の数を減らす。全国基本取得をカットする前に利用先のAPIと費用を点検
- 季節、雷・強風・大雨、地形、海岸・山沿いなどの検証が必要なら、単純に距離だけで重点地点を選ばず、地理的・気候的な偏りを防ぐ
- 全国の公開観測値は、契約や許諾を得た**全国一括の配信データ**で取得する。気象庁Webの過去データCSV画面を多数の観測所へ反復スクレイピングしない
- 原則、降水量の観測値は1時間積算、風は計測方法・時刻・高さに注意。欠測と未測定は正解0としない

## スケーリング見積もり（概算）
1300地点 × 3モデル × 1回/日 = **3900 地点・モデル予報スナップショット/日**。
重点100地点の追加3回/日 × 3モデル = **900 地点・モデルスナップショット/日**。
合計 **4800 地点・モデルスナップショット/日**。
- これはHTTPリクエスト数やOpen-Meteoの課金上の「API call」の換算値ではない。座標バッチ等のAPI仕様、料金体系、リトライ、失敗で変化する
- 全観測所の1時間あたり1件の観測値を保存する場合、約31,200地点・時刻レコード/日。風の検証に使えるのは計測する観測所だけ
- 収集と評価の実行はサーバー側に置き、まとめ結果だけを地域単位で公開。iPhoneが全国の履歴を毎回読み込むようにしない
- 全国の予報の生データを何年分も公開GitHubのJSONLへ積み上げない。長期保存には管理付きDBや期限つきアーカイブ、地域別集計を用意
- **1回/日の全国収集**は基礎検証に過ぎず、3/6/12時間先の精度の比較条件が各モデルで揃わない可能性がある。比較対象時刻・予報リード時間の共通サンプル数を表示する

## 今回の実装：通信しない計画生成器
`tools/nationwide_collection_plan.py` は、公開メタデータの**ローカルファイル**を読み込んで全国の収集計画を出すだけ。
- 既定は1日4つのUTC枠（00,06,12,18）。全国の各地点は各モデル1日1回、重点地点だけ4回
- 全国全地点の最低取得回数が予算で確保できないなら実行を拒否する。静かに対象地域を落とさない
- データを手動で準備して以下のように実行（例、設定だけで通信なし）：

```sh
python3 tools/nationwide_collection_plan.py --station-catalog /path/to/amedastable.json --date 2026-11-10 --max-site-model-jobs 5500
```

重点地点を指定したいとき（公開の観測所IDのみ、個人GPSや現場名は渡さない）：

```sh
python3 tools/nationwide_collection_plan.py --station-catalog /path/to/amedastable.json --focus-station-ids 31111,31602 --jobs-output /tmp/nationwide-plan.json
```

「現在地から近い場所だけ高頻度」は**まだ自動実装していない**。サーバーにGPSを無断送信しないため、将来の設定画面で「全国一律」「任意の都道府県を重点」「現在地周辺の重点化を明示許可」などを選べるように検討する。

## 使用開始に必要な条件（未完）
- 気象庁の自動取得を許可されたアメダス配信経路（地域気象観測報等）を確保。気象庁過去データDLは過度な自動アクセスを控えるよう明記
- Open-Meteo無料APIは非商用・アクセス制限あり。伐採会社での業務に使う場合は適切な商用ライセンスなどを確認し、勝手に課金しない
- 提供元の発表時刻・データ遅延・品質フラグを検証し、観測値と予報の積算期間をそろえる
- 全国データの上限、障害の検知と再試行、90日原本保持と長期集計、費用上限を設定
- まず少数の試験地点で実測との突合に成功させてから段階拡大
- 観測所と山林・高所・樹上は風の状況が違う。作業可否は会社の基準・実地確認・気象庁の警報を優先
