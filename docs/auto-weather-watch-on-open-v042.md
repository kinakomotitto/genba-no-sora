# 現場の空 v0.42 — 気象変化通知は初回設定だけ、その後はアプリを開くたび自動で現在地を更新

更新：2026-11-11。対象機能：v0.41の雨・強風・雷雨の**モデル参考予報通知**。公式の気象警報や雷接近の実況監視ではありません。

## ユーザー要望
「1回だけ最初に設定したら、その後はアプリを開くたび自動的に現在地を更新し、閉じている間も最後の地点について気象変化を通知してほしい」

## 変更内容

1. **最初の1回だけ本人の操作が必要**：「現場 → 通知設定 → ポケットに届く天気変化通知 → 📍 初回設定：開くたび自動監視をオンにする」。位置情報のサーバー送信について画面に明記し、本人がボタンを押し、Web Push通知の許可、GPS取得、通知サーバー登録のすべてが成功した後でのみ、端末の `localStorage['genbanosora.weatherwatch.auto.v1']='on'` に継続同意を保存する
2. **2回目以降は自動**：アプリ起動時に新しいGPSを要求し、保存された同意があり、登録済みWeb Pushの権限が有効で、サーバーが使える場合に限り、丸めた座標を `/api/weather-watch-enable` へ更新。アプリがスリープから前面へ戻ったときも同様に再測位する。短時間に同じGPSが連続した場合は2分間の重複問い合わせを抑えるが、位置が変わった場合は即更新
3. **閉じた間は最後の地点の監視**：既存v0.41のサーバーCronが約15分間隔でモデル予報を確認。最後のGPS更新から4時間で監視は期限切れとなり、その地点の通知を止める。4時間経過後でも、端末に「継続同意」が残っていれば、次にアプリを開いたときの新しいGPSで再開できる
4. **停止はいつでも可能**：「通知監視を終了・位置情報を削除する」を押すと、端末の自動更新同意をすぐ解除し、進行中のサーバー更新の後で停止／GPS削除APIを呼ぶ。通信エラー時は自動更新をOFFのままにし、**サーバーの停止を確認できなかった**旨を表示して再試行できるようにする。期限切れ時も停止ボタンは表示し続け、端末の継続同意を解除できる
5. **通知をすべてオフ**：既存の一括通知解除でも、先に自動更新同意を解除。すでにサーバーへ送信中のGPS更新があれば終わるのを待ち、登録解除する
6. **安全な失敗**：GPS精度が300mより大きい、GPS取得失敗、通知権限消失、非PWA、オフライン、Push購読消滅、サーバー障害の場合はGPSを**自動送信しない**。監視期間が残っている古い地点は期限まで残り得るので、画面に注意文を出す。位置情報はアプリを開いただけで無条件に送られるものではない

## 重要な制限

- iPhoneホーム画面のWebアプリは**閉じたまま新しいGPSを追跡することができない**。移動後にアプリを開かない限り、通知の対象は最後に正常更新した地点のまま
- アプリを閉じたまま4時間を過ぎると監視期限切れ。**サーバーは自動的に次の4時間へ継続しない**。ただし、次にアプリを開けば保存した同意に基づき再開できる
- 新しいGPSを取得するたび位置データを小数3桁へ丸め、本人が同意している間だけCloudflare通知サーバーに送る。予報照会のためOpen-Meteoにも丸めた座標を送る。保存現場名・観測メモ・実測記録は送らない
- 「この先2時間」の雨・最大瞬間風速・雷雨予報の参考通知であり、分単位の降り始め予想や落雷の実況接近ではない。通知の遅延・見逃し・誤報の可能性があり、現場の判断では最新の気象庁情報と会社の安全基準を優先する

## テスト・運用

- `tests/test_weather_watch_autorefresh.cjs`：実際のアプリ内の継続同意／自動更新関数を抽出してオフライン実行。初回同意前の送信禁止、1回の同意後の自動送信、同じ地点の重複防止、移動先の座標変更、古いGPS拒否、閉じたアプリからの送信防止、通知権限消失時の送信防止、停止時の継続同意削除、再起動した場合の自動再開、サーバー送信中の停止操作を検証
- 既存のホーム・現場・日本語位置ラベル・3モデル照合・天気記録・Web Pushのテストを継続
- iPhoneのPWAオフラインキャッシュを v0.42 に更新
- **実機での最終確認が必要**：Web Push通知を受信できるか、アプリを閉じた後の再起動・復帰でGPS許可と自動監視更新ができるかは、iPhoneの状態・OS側の制限とCloudflare本番設定にも依存する
